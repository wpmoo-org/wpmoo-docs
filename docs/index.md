## Stop Rebuilding The Same Odoo Setup

Odoo teams spend too much time on the same environment chores: Compose files,
addon paths, source repository layout, update commands, test commands,
database snapshots, and recovery scripts.

WPMoo Toolkit gives those chores one repeatable workflow. It creates the local
environment, keeps product source repositories separate, and gives developers a
cockpit for the module work they run every day.

It is free, MIT-licensed, local-first tooling. Your source code stays in your
repositories. The generated environment stays inspectable, refreshable, and
replaceable.

## Built For Odoo Module Work

| Without WPMoo | With WPMoo |
| --- | --- |
| Each project grows its own local setup conventions. | Every product gets a predictable generated environment. |
| Addon repositories drift into ad hoc paths. | Sources live under `private`, `oca`, and `external`. |
| Developers memorize Docker and Odoo command details. | Daily work runs through `./moo` or the cockpit. |
| Risky changes happen without a clear rollback point. | Snapshots and restore workflows are first-class. |
| Diagnostics are scattered across logs and shell commands. | `status` and `doctor` show actionable environment checks. |

## Quick Start

Run the setup wizard:

::: code-group

```sh [npm]
$ npx @wpmoo/toolkit
```

```sh [pnpm]
$ pnpm dlx @wpmoo/toolkit
```

```sh [yarn]
$ yarn dlx @wpmoo/toolkit
```

```sh [bun]
$ bunx @wpmoo/toolkit
```

:::

Enter the generated environment:

```sh
$ cd <product>_dev
$ ./moo
```

Start Odoo and work on a module:

```sh
$ ./moo start
$ ./moo update my_module
$ ./moo test my_module
```

GitHub CLI is optional. You can start local-only and add source repositories
later from the cockpit or direct commands.

## The Cockpit Covers The Daily Loop

```text
Services      start, stop, restart, logs, shell
Modules       install, update, test, lint, translate, scaffold
Database      psql, snapshot, restore, reset
Diagnostics   status, doctor
Repositories  add source repo, remove source repo
Maintenance   safe reset generated files
```

Every cockpit action also has a direct command, so the same workflow works for
interactive developers, scripts, CI, and coding agents.

## A Typical Day With WPMoo

```sh
$ ./moo start
$ ./moo update sale_custom
$ ./moo test sale_custom
$ ./moo snapshot dev before-refactor
$ ./moo doctor
```

No long Docker commands. No guessing addon paths. No mixing generated runtime
files with product source code.
